# LVS 結果の解析 — `lef/LVS_error.lvsdb`

## 第5回（2026-09-10 08:30）— ADD ポート入れ替わりは解消。残り2件の原因を特定

### 結果

| 回路 | 結果 |
|---|---|
| `ADDBUF` | 一致（**曖昧マッチの警告5件が消滅** — 前回のピンラベルが効いた） |
| `DEC2` / `REGBUF` / `TLAT` | 一致 |
| `REG4x16` | 不一致 — 残りエラーは `WEB` `$I75` `$I76` `$I77` の4ネットのみ |

`Port mismatch 'ADD[0]' vs. 'ADD[3]'` 系の4件は**消えた**。原因は別々の2つだった。

---

### 原因(1) ソースネットリスト — `web` と `WEB` が同一ネットに潰れていた

**SPICE は大文字小文字を区別しない。** トップの記述

```
XADDBUF ADD[0..3] WEB  a0 ab0 … web  vdd vss ADDBUF
                  ↑入力(WEB_PIN)      ↑出力(WEB)
```

は読み込み後に**両方とも `WEB`** になり、WE バッファ2段の入力と出力が短絡した回路として
比較されていた。抽出後のリファレンス側で ADDBUF インスタンスの pos4 と pos13 が
どちらも `WEB` に繋がっていることで確認。これが `WEB` / `$I75` のエラー。

→ 内部線を **`WEBI`** に改名（`scripts/mkspice.py` の `W_INT`）。
全サブサーキットで大文字小文字の衝突が他に無いことも確認済み。

### 原因(2) DEC2 の bit0 が逆に割り当てられていた

`$I76` / `$I77` のエラーはこちら。DEC2 単体では2行が構造的に等価なので、
`A0`/`AB0` のどちらを偶数行に割り当てても同型。KLayout は恣意的に

```
Matching nets $17 vs. RDBE from an ambiguous group of nets
  レイアウト pin0 → リファレンス AB0
  レイアウト pin1 → リファレンス A0     ← ADDBUF の名前と逆
```

を選んでいた。ADDBUF 側が名前で固定された今、これと矛盾する。

**正しい対応を2通りの独立な方法で確認した。**
DEC2 は REG4x16 内で 90° 回転して置かれる（`M O(90)`, 変位 −86.4）ので
DEC2ローカル y → REG4x16 x = y − 86.4:

| DEC2 ローカル | REG4x16 x | ADDBUF 出力ピン | 意味 |
|---|---|---|---|
| y = 18.9 | −67.5 | `A0` (ADDBUFローカル x=18.9) | **A0** |
| y = 24.3 | −62.1 | `AB0` (x=13.5) | **AB0** |
| y = 13.5 | −72.9 | `WEB` (x=24.3) | **WEB** |

抽出ネットリストのピン対応（pin0←`$I77`=a0 / pin1←`$I76`=ab0 / pin2←`$I75`=web、
全8インスタンスで共通）とも完全に一致。

該当位置には **via 付きの M2 ランディングパッド**が既にあったので、そこに 49/0 で:

```
DEC2:  A0 @ (0.0, 18.9)   AB0 @ (0.0, 24.3)   WEB @ (31.8, 13.5)
```

bit1〜3 は直列スタック中の位置が違うので構造的に区別でき、ラベル不要
（`following an ambiguous match` = 確定済みの意味）。

### ラベル層の注意

デッキは `drc/00_Layers.drc` の

```ruby
M1_LBL = labels(48, 0)    # M1 ラベル
M2_LBL = labels(49, 0)    # M2 ラベル
```

**48/0 と 49/0 からしかテキストを拾わない。** 48/1 や 49/1 に置いても無視される
（DEC2 の既存 `vdd`/`vss` は 49/1 なので効いていない。DEC2 は一致しているので放置）。
ラベルは配線の層に合わせる — M1 上なら 48/0、M2 上なら 49/0。

### 原因 — ADDBUF のピンに名前が無い

`ADDBUF` は **INV 2段の channel が4本、構造的に完全に同一**。
KLayout の LVS は**サブ回路を先に単体で比較**するので、`ADDBUF` を比べる時点では
どの channel が bit0 でどれが bit3 かを決める手掛かりが何も無い（レイアウト側のピンが
無名 `$2, $3, …`）。そこで恣意的に対応を決めてしまう:

```
Matching nets $2 vs. AB0 from an ambiguous group of nets
Matching nets $3 vs. AB1 from an ambiguous group of nets
Matching nets $4 vs. AB2 from an ambiguous group of nets
Matching nets $5 vs. AB3 from an ambiguous group of nets
Matching nets $6 vs. WT  from an ambiguous group of nets
```

いったん決まった channel 対応はトップに持ち上がるので、トップで
`ADD[0..3]` を名前で合わせようとすると矛盾し、ポート不一致として出る。

> 16行のワードは互いに構造的に等価なので、**アドレスbitを並べ替えても行が
> 並べ替わるだけ**で回路全体としては同型のまま（自己同型）。
> LVS には原理的に区別できない。名前で縛るしかない。

### レイアウトは正しい（幾何・接続を追って確認済み）

`lef/LVS_error.lvsdb` の抽出結果から ADDBUF の INV チェーンを復元:

| ADD ピン | 1段目出力（相補） | 2段目出力（真） |
|---|---|---|
| `ADD[0]` | `$I76` | `$I77` |
| `ADD[1]` | `$I83` | `$I80` |
| `ADD[2]` | `$I79` | `$I81` |
| `ADD[3]` | `$I82` | `$I78` |
| `WEB` | (内部 `WT`) | `$I75` |

DEC2 を8個ぶん並べて、各ピン位置が全インスタンスで一定か／何個ごとに切り替わるかを見る:

| DEC2 ピン位置 | 接続 | 意味 |
|---|---|---|
| pos0 / pos1 | `$I77` / `$I76` **全8個で共通** | **bit0**（DEC2 の中で2行を分ける） |
| pos13 | 1個ごとに `$I83`↔`$I80` | **bit1** |
| pos14 | 2個ごとに `$I81`↔`$I79` | **bit2** |
| pos15 | 4個ごとに `$I78`↔`$I82` | **bit3** |
| pos2 | `$I75` 共通 | `web` |

→ **`ADD[0]` が LSB、`ADD[3]` が MSB。設計意図どおり。**

さらに、DEC2 の8グループが 16行の TLAT にどう配られているかも確認した。
**8グループが各2行ずつ、重複なく全16行を覆っている**（全単射）。
物理的な並び順は Y 昇順で アドレスグループ 6,7,4,5,2,3,0,1 と単調ではないが、
アドレス→行が1対1である以上、動作上は完全に問題ない。

## 第4回に向けて（2026-09-10 06:19）— 直列スタックの順序を修正、**全回路が同型で一致**

### 第3回の結果

| 回路 | 結果 |
|---|---|
| `ADDBUF` / `TLAT` / `REGBUF` | 一致 |
| `DEC2` | 不一致（ただし**ピン数は 16 で揃った** — タップ追加が効いた） |
| `REG4x16` | スキップ |

タップ追加により抽出 DEC2 は `PMOS bulk = $14(vdd)` / `NMOS bulk = VSS` となり、
電源ピンが 2 本に戻った。残る差は**直列スタックの順序 2 箇所**だった。

### 原因 — 直列トランジスタの並び順

MOSFET の直列スタックは、途中のノードが別ネットになるため**並び順が回路の一部**になる。
抽出結果を読み解くと、レイアウトはこちらの記述と逆だった。

| | レイアウト（正） | 修正前のソース（誤） |
|---|---|---|
| **NAND4 の NMOS 直列** | vss 側から **bit3, bit2, bit1, bit0** | vss 側から bit0, bit1, bit2, bit3 |
| **NOR2 の PMOS 直列** | vdd 側から **WEB, RDB** | vdd 側から RDB, WEB |

抽出 DEC2（右半分）の該当箇所:

```
XM$17 VSS  $I27 $34 VSS   ← vss 側の先頭が $I27 = bit3
XM$18 $34  $I40 $28 VSS
XM$19 $28  $I41 $29 VSS
XM$20 $29  $2   $17 VSS   ← 出力 $17(RDB) 側が $2 = bit0

XM$11 $14  $5   $16 $14   ← vdd 側が $5 = WEB
XM$12 $16  $17  $15 $14   ← WR 側が $17 = RDB
```

（$I41/$I40/$I27 が bit1/2/3 であることは、8個の DEC2 インスタンスで
それぞれ 1回/2回/4回ごとに切り替わることから確定した。）

### 修正して、LVS を回す前に同型判定で検証した

`scripts/netcmp.py` を追加した。SPICE を読んでグラフ同型判定（networkx VF2）を行う、
LVS の予行演習用ツール。

```sh
python3 scripts/netcmp.py spice/REG4x16_src.spi DEC2 lef/REG4x16.extracted DEC2 --map '...'
```

**結果 — 全回路が同型で一致:**

| 回路 | 素子 | 判定 |
|---|---:|---|
| `TLAT` | 12 | **一致** |
| `REGBUF` | 8 | **一致**（`D ↔ $5` = 出力側。書込方向も確定） |
| `ADDBUF` | 20 | **一致** |
| `DEC2` | 32 | **一致**（今回の修正で） |
| **`REG4x16` トップ** | 77 インスタンス | **一致**（トップピンを同名固定しても一致） |

`lef/simulation/REG4x16.spice` 更新済み。**次の実行で通るはず。**

> トップ比較で D[0..3]/Q[0..3] は4ビットが構造的に等価なので、名前ヒント無しだと
> 巡回置換で対応してしまう。名前を固定して判定し直しても一致することを確認済み。

## 第3回に向けて（2026-09-10 06:15）— DEC2 にタップを追加

レイアウトの DEC2 に **N-well タップと基板タップが追加された**ので、
ソースネットリストの電源ピンを 4本 → **2本**に戻した。

GDS で確認した内容:

| | 位置 | コンタクト | 接続先 M1 |
|---|---|---:|---|
| **N-well タップ**（新規） | x −1.30..1.30, y 81.80..84.40 | 1 | **PMOS 活性と同じ M1**（vdd レール） ✓ |
| 基板タップ | x ±53.30..55.90（全高） | 32 | **NMOS 活性と同じ M1**（vss レール） ✓ |

- PMOS 活性と NMOS 活性の両方に繋がる M1 成分は無い → **電源短絡なし** ✓

```
.subckt DEC2 A0 AB0 A1 A2 A3 WEB WRE WRBE RDE RDBE WRO WRBO RDO RDBO vdd vss
```

**16ピン**（アドレス5 + WEB 1 + ワードライン8 + 電源2）。
`lef/simulation/REG4x16.spice` 更新済み。ランセットの修正は不要。

### 残っていた食い違い 2件（どちらもソースネットリスト側の記述漏れ）

抽出された DEC2 のピンは **18本**、こちらの記述は **19本**だった。突き合わせて原因を特定した。

#### (1) アドレスの bit1–3 は2行で共有されている

`DEC2` は行 2k と 2k+1 を含む。この2行は **bit0 しか違わない**ので、
bit1/2/3 のデコード入力は**物理的に同じネット**を2行で共有している。

8個の DEC2 インスタンスの接続を並べると明らか:

```
X$9    pos2,3,4=[$I77 $I76 $I75]   pos15,16,18=[$I80 $I81 $I78]
X$10   pos2,3,4=[$I77 $I76 $I75]   pos15,16,18=[$I83 $I81 $I78]
X$11   pos2,3,4=[$I77 $I76 $I75]   pos15,16,18=[$I83 $I79 $I78]
...                ↑全インスタンス共通            ↑8通りに変化
       = a0 / ab0 / WEB                       = bit1,2,3（インスタンスごと）
```

→ アドレスピンは **8本ではなく 5本**（`A0`, `AB0`, `A1`, `A2`, `A3`）。

#### (2) DEC0/DEC2 にはウェル／基板タップが無い

抽出 DEC2 では **レールとバルクが別ネット**になっている:

| | レール | バルク |
|---|---|---|
| PMOS | `$14` → トップで `vdd` | `$I38`（N-well）→ トップで `vdd` |
| NMOS | `$1` → トップで `vss` | `VSS`（基板）→ トップで `vss` |

トップ（REG4x16）では両方とも同じ `vdd` / `vss` に繋がるので**電気的には正しい**。
セル内にタップが無いため、DEC2 の境界で別ピンとして出てくるだけ。

> `TLAT` / `REGBUF` は**セル内に全幅のタップ帯を持っている**ので、
> レールとバルクが同一ネットになり、電源ピンが2本で済んでいる。だから一致した。
> DEC0/DEC2 だけがこの点で異なる。

→ 電源系ピンは **2本ではなく 4本**（`vdd`, `vss`, `vnw`, `vsub`）。

**5 + 1(WEB) + 8(ワードライン) + 4(電源) = 18 ✓** 抽出と一致。

### 対処（適用済み）

`scripts/mkspice.py` を修正し、`lef/simulation/REG4x16.spice` を更新した。

```
.subckt DEC2 A0 AB0 A1 A2 A3 WEB
+            WRE WRBE RDE RDBE WRO WRBO RDO RDBO
+            vdd vss vnw vsub          ← バルクを分離
   E = 偶数行 2k   （bit0=0 → AB0）
   O = 奇数行 2k+1 （bit0=1 → A0）
   A1..A3 は2行で共有
   PMOS: ... vdd vnw PMOS   /  NMOS: ... vss vsub NMOS
```

トップでの接続（`vnw`→`vdd`, `vsub`→`vss` を結ぶ）:

```
XDEC2_0 a0 ab0 ab1 ab2 ab3 web wr0 wrb0 rd0 rdb0 wr1 wrb1 rd1 rdb1 vdd vss vdd vss DEC2
XDEC2_1 a0 ab0 a1  ab2 ab3 web wr2 wrb2 rd2 rdb2 wr3 wrb3 rd3 rdb3 vdd vss vdd vss DEC2
...
```

**ランセットの修正は今回も不要。** そのまま再実行する。

> 別解: レイアウトの DEC0/DEC2 にウェル／基板タップを入れれば電源ピンは2本になり、
> `TLAT` と同じ扱いにできる。面積は増えるが DEC2 を単体セルとして扱いやすくなる。
> 今のところ急ぐ必要はない。

## 第1回（2026-09-10 05:27）— DEC0 単位

### 結果

`DEC0` のみ不一致、`REG4x16` はスキップ。抽出 DEC0 は **6 素子**、参照は 16 素子。
残り 10 素子 × 16行 = **160 素子がトップに昇格**していた（総数 1,076 は一致）。

### 原因

KLayout の deep 抽出は**複数セルにまたがって形成されるデバイスを親に昇格させる**。
DEC0 の左端の拡散が、`DEC2` 内で X ミラーした隣の DEC0 と重なる領域（x < 2.4）に
はみ出しており、そこから NAND4 のソース／ドレイン共有チェーンが繋がっている。

```
PMOS 島8 (x -1.30..1.50) ★重なり領域に侵入
   └ g1.5 ─ 島7 ─ g5.5 ─ 島6 ─ g9.5 ─ 島5 ─ g13.5 ─ 島4 ─ g19.5 ─ 島3 ─ g21.7  → 6個
NMOS 島10 (x -0.30..2.50) ★
   └ g2.5 ─ 島9 ─ g4.7 ─ 島8 ─ g6.9 ─ 島7 ─ g9.1                             → 4個
```

拡散を隣とわざと共有する密度最適化なので**バグではない**。ただし DEC0 は自己完結しない。

### 対処

**DEC2 を最小単位にした。** DEC2 は自己完結している（隣接 DEC2 との重なり帯に侵入する
拡散島は無く、あるのは P+ 基板タップ列だけで、poly も N-well も無いのでデバイスにならない）。

ソース側から `DEC0` を無くしたので、`align` が自動で DEC0 を DEC2 にフラット化した。

## 副次的に見つかったラベルの問題（合否には影響していない）

| ネット名 | 状況 |
|---|---|
| `gnd,vdd` | REGBUF の **下側（gnd）レールに `vdd` ラベル**が載っている（35.10, 2.50）。`gnd` は (2.70, 2.40) |
| `D,DD` | REGBUF の `D` ラベルが**入力側**に載り、出力ネットが無名になっている |
| DEC0/DEC2 | vdd/gnd のラベルが1つも無い |

短絡ではない（短絡なら REGBUF が一致しない）。接続そのものは正しく、抽出トップを追うと
`D[0] → REGBUF入力 → 2段INV → TLAT.D`、`TLAT.Q → REGBUF.Q → 2段INV → Q[0]` と繋がっている。

ただし `run.lvs` は `flag_missing_ports` を有効にしているので、
トップ比較まで到達したときに引っかかる可能性がある。先に直しておくと安全。
